# NASB1995 フロントエンド

教会の賛美歌と聖書を管理・検索する Web アプリのフロントエンドです。
Next.js 16(App Router)/ React 19 / Tailwind CSS v4 / shadcn/ui で作られています。

## 特徴

### 公開ホーム(ログイン不要)

- 画面幅で表示が切り替わります。PC は開いた賛美歌集(左ページに目次、右ページに選んだ曲)、モバイルは横スワイプのカード(終わりに近づくと自動で追加読み込み)です。
- 検索は、サーバー側の検索(ハングル・`*` `★` `#` 付き・`&` 区切り)と、ブラウザ内の検索(日本語・英語の曲名と歌詞)を自動で振り分けます。
- 一致度(よく一致・一致・やや一致・関連)を色や記号で示し、歌詞の一致箇所に下線を引きます。
- 調号つきの五線譜を描き、選んだ調の楽譜(PDF)をダウンロードできます。

### 管理画面(ログイン後)

- **賛美歌一覧**: 検索、ページ送り、YouTube を開く、楽譜のアップロード・ダウンロード、検索結果から YouTube プレイリストを作成します。追加・編集・楽譜アップロードはモーダルで行い、一覧の検索条件やページを保ったままです。
- **楽譜**: 12 長調ごとに登録します。同じ調に違う内容があれば上書きを確認し、オリジナルキーは 1 曲に 1 つです。上限は 30MB です。
- **ランダム選択**: 賛美歌を 5 曲選びます。ヘッダーの検索からも使えます。
- **聖書章節入力**: 書・章を連動して選び、節の本文を英語と日本語で入力します。登録済みの節は更新になり、`{{...}}` の記法で赤字を扱えます。
- **個人設定**: YouTube 連携のオン・オフ(Google の同意画面へ遷移)。

### 操作性

- 入力中の内容があるまま画面を離れようとすると確認します(タブを閉じる・再読み込み・画面内の移動・モーダルを閉じる)。
- 別の端末でログインされると、強制ログアウトして理由を表示します。
- 確認ダイアログやトーストは、全画面で共通の部品です。

### 技術面

- UI は shadcn/ui(Radix)で統一しています。状態は Zustand、サーバーデータは TanStack Query で扱います。
- `output: "standalone"` で、Next.js 自身の Node.js サーバーが配信する Docker 構成です(ポート 3000)。
- `/api` は、開発時だけ `next dev` が `http://localhost:8277` へ転送します。本番は前段(nginx・CloudFront など)がバックエンドへ直接転送する前提です。

## テスト

| コマンド | 内容 |
|---|---|
| `npm test` | ユニットテスト(Vitest)。`src/**/*.test.ts` |
| `npm run test:watch` | ユニットテストを変更のたびに実行 |
| `npm run e2e` | 画面を通したテスト(Playwright)。`e2e/` |
| `npm run typecheck` | 型チェック(`tsc --noEmit`) |

- E2E はバックエンドを起動しません。ブラウザから出る `/api/**` を `e2e/mock-api.ts` が受けて応答します。
- `npm run e2e` は本番ビルド(`npm run build`)をしてから、Dockerfile と同じ standalone のサーバーをポート 3100 で起動します。
- 初めて E2E を動かすときは、先に `npx playwright install chromium` でブラウザを用意してください。
- GitHub Actions(`.github/workflows/ci.yml`)が、`main` への push とプルリクエストのたびに Lint・型チェック・ユニットテスト・ビルド・E2E を実行します。
