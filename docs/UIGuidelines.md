# NASB1995 フロントエンド 画面デザインの決まり

## 1. 文書の目的

本書は、画面の配色・文字・大きさ・部品の見た目について、現行実装で決めている内容をまとめたものである。機能・画面遷移・通信の設計は [DesignDocument.md](DesignDocument.md) を参照する。値は2026年11月21日時点の本リポジトリのソースを根拠とし、変更時は本書も併せて更新する。

構成と説明の書き方は `../nasb-vue/docs/UIGuidelines.md` を参考にする。本書の値は Tailwind CSS と shadcn/ui（Base UI + Nova）の実装に基づく。rem の px 換算はブラウザの基準文字サイズ16pxを前提とする。

## 2. 基本方針

- **shadcn/ui の公式部品は `base-nova` の CLI 生成コードをそのまま使い、生成ファイルの直接編集を禁止する。** `src/components/ui/` 配下と `src/hooks/use-mobile.ts` などの付属ファイルも対象とする。追加・更新は CLI で生成・再生成する。
- Dialog・Popover・Select・Sidebar などで使うプリミティブの操作とフォーカス管理は Base UI、カルーセルは Embla が担う。画面固有の見た目は呼び出し側の props・`className` やアプリ側の CSS で指定する。
- 主な操作は `primary`、危険な操作は `destructive`、補助操作は `outline`・`ghost` を使う。Vue 版の `secondary`（青）・`success`（緑）等の役割は持ち込まない。
- アイコンは `lucide-react` を使用する。エルサレム十字、五線譜、ト音記号・調号は専用の SVG 部品を使う。
- 全体のテーマ切り替え UI や ThemeProvider は設けていない。本文は `:root` の配色を基準にし、CSS に残る `.dark` の指定だけでダークモード対応済みとは扱わない。
- PC とモバイルの境目は幅768pxとする（Tailwind の `md`）。ホームの表示切り替えとログイン・管理画面に入るときの判定には同じフックを使う。管理画面のサイドバーは公式部品に付属するフックを使う。
- 文字だけで分からないアイコン操作には `aria-label` と Tooltip・Hint を付ける。処理中は Spinner・Skeleton 等で状態を示す。

主な定義は [globals.css](../src/app/globals.css)、[公式 Button](../src/components/ui/button.tsx)、[ホームの画面幅判定](../src/hooks/use-mobile-viewport.ts)、[Sidebar の画面幅判定](../src/hooks/use-mobile.ts) にある。

## 3. 配色

### 3.1 デザイントークン（`src/app/globals.css`）

| 名前                                 | 色                    | 主な用途                                     |
| ------------------------------------ | --------------------- | -------------------------------------------- |
| `background`・`card`・`popover`      | `#ffffff`             | 白い面・カード・ポップオーバー               |
| `foreground`                         | `#1f2937`             | 標準文字                                     |
| `primary`                            | `#800020`             | 臙脂。主要ボタン、ロゴ、選択状態、フォーカス |
| `primary-foreground`                 | `#ffffff`             | 主要ボタンの文字                             |
| `secondary` / `secondary-foreground` | `#f5eef0` / `#4a0a1a` | 控えめな塗りの操作                           |
| `muted` / `muted-foreground`         | `#f3f4f6` / `#4b5563` | 補足の背景・文字                             |
| `accent` / `accent-foreground`       | `#f9f0f2` / `#800020` | ホバー・選択の背景と文字                     |
| `destructive`                        | `#b91c1c`             | 削除などの危険な操作、入力エラー             |
| `border` / `input`                   | `#e5e7eb` / `#d1d5db` | 枠線・入力欄の枠                             |
| `ring`                               | `#800020`             | フォーカスリング                             |

角丸の基準 `--radius` は0.625rem（10px）とする。shadcn/ui 用の既定の枠線色は `[data-slot]` とその子に限って適用し、既存画面全体の枠線を一律に変更しない。

`destructive` は、白背景における操作時の文字の読みやすさを優先して選ぶ。通常サイズの文字は [WCAG 2.2 AA の基準](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) に従い、以下の組み合わせで4.5:1以上を確保する。半透明色は白に重ねた場合の概算とする。

| 状態                               | 文字 / 背景                                     | コントラスト比 |
| ---------------------------------- | ----------------------------------------------- | -------------: |
| 危険操作ボタンの通常時             | `destructive` / `destructive` 10%を白に重ねた色 |       約5.46:1 |
| 危険操作ボタンのホバー時           | `destructive` / `destructive` 20%を白に重ねた色 |       約4.57:1 |
| 危険操作メニュー項目のフォーカス時 | `destructive` / `destructive` 10%を白に重ねた色 |       約5.46:1 |

### 3.3 一致度の色と記号

| 一致度                | PC ホームの文字・記号 | 管理一覧のバッジ              | モバイルのカード背景       |

PC の記号と管理一覧の文言は検索時に表示する。モバイルはカード自体の色に反映する。曲の詳細シートは一致度に合わせて臙脂・深緑・濃い黄褐色を使い、それ以外は濃い茶色を使う。

### 3.4 調の表示

調ごとの固有色は設けない。PC ホームは選んでいない調を透明地・金色の枠・濃色の文字、選んだ調を青の塗り・白文字とする。アップロードでは選択中を `primary` にする。

通信では `Bb` 等の ASCII 表記を使い、表示は `B♭` 等にする。アップロードの選択順は A、B♭、B、C、D♭、D、E♭、E、F、G♭、G、A♭。取得した調の表示順は API の返却順とする。オリジナルキーは PC ホームで「＊」、ダウンロード用の Popover・Dialog で「\*」を付ける。

## 4. 文字

| 用途                                       | 書体・指定                                        |
| ------------------------------------------ | ------------------------------------------------- |
| `.noto-sans`                               | Noto Sans JP                                      |
| `.noto-serif`                              | Noto Serif JP、Noto Serif KR の順のフォールバック |
| PC ホームの基本書体                        | Noto Serif JP、Noto Serif KR                      |
| PC ホームの韓国語名・歌詞                  | Noto Serif KR                                     |
| PC ホームの補助操作 `.book-sans`           | Noto Sans JP                                      |
| ホーム・管理サイドバーのロゴ               | Niconne                                           |
| 賛美歌フォーム・楽譜登録・本人情報         | `.noto-sans`                                      |
| 確認ダイアログ、管理一覧本文、赤字エディタ | `.noto-serif`                                     |

Noto 系は [src/app/fonts.ts](../src/app/fonts.ts) で Fontsource の CSS を全体に読み込む。Noto Serif JP・KR は400・600・700、Noto Sans JP は400・500・700を使う。文字範囲ごとのファイルを自前配信し、`font-display: swap` とする。Niconne は Latin 400 の WOFF2 を `next/font/local` で読み込み、CSS 変数 `--font-niconne` を `<html>` に付ける。

`body` に Noto Sans JP を一律適用する指定はないため、画面や部品で上記クラスを使う。ログイン画面は Noto Sans JP を使い、ボタンの800と見出しの900を画面から読み込む。

## 5. ロゴ・共通の面と操作

### 5.1 ロゴ

エルサレム十字は [JerusalemCross.tsx](../src/components/JerusalemCross.tsx) を使用する。ホームでは十字と文字を1つのボタンにまとめて検索をリセットし、管理サイドバーではメインメニューへ移動する。

| 場所                         | 大きさ・色                                                      |
| ---------------------------- | --------------------------------------------------------------- |
| PC ホーム                    | 十字36px、文字28px。ともにクリーム色 `#f3e3c3`                  |
| モバイルホーム               | 十字66px。文字は `.effect-shine` の1.8remが適用され、臙脂で表示 |
| 管理サイドバー               | 40pxのアイボリー角丸面に28pxの臙脂の十字、文字はアイボリー      |
| 管理サイドバーの折りたたみ時 | 32pxの面に20pxの十字、文字を隠す                                |

`.effect-shine` はホバー時に白文字と水色の光を1500msの交互アニメーションで表示する。PC ホームの `.open-hymnal-logo` にはこの効果を使わない。

### 5.2 背景とガラス表現

- 背景画像は `PageBackground` で画面全体の背面に固定し、`object-fit: cover` で表示する。装飾画像は読み上げの対象外とする。
- 管理画面の `.glass-panel` は白82%、背景ぼかし6px、白45%の1px枠、外側の影と上辺の内側ハイライトとする。ホバー時は枠を白80%にする。対象画面のカードの角丸は18px。
- モバイルホームの `.glass-card` は白33%を基準に、ぼかし20px・彩度180%、白45%の1px枠、角丸18pxとする。スライド内の最小高さは44vh、内側余白は24px。
- ボタンは Nova の公式 Button を使う。標準は高さ32px（`h-8`）、小型は28px（`h-7`）、大型は36px（`h-9`）。キーボードフォーカスではリングを表示する。ポップアップを開くボタンを除き、押している間は下へ1px移動する。画面固有の寸法や効果は呼び出し側で指定する。

## 6. ホーム

### 6.1 PC（幅768px以上）

- ヘッダーは高さ64px、左右余白40px、要素間24px。左にロゴ、中央に下線だけの検索欄、右に透明地・クリーム色の枠のログインボタンを置く。
- 検索欄は `min(420px, 40vw)`。左に「索引」、右に検索アイコンを置き、取得中はアイコンを Spinner にする。
- 見開きの本は幅最大1190px、高さ740px。メイン領域の余白は上6px・左右24px・下26pxで、余白内の中央に置く。低い画面でも本の高さは縮めず、ページ全体をスクロールする。
- 左ページは幅40%、余白は上24px・右30px・下14px・左32px。右ページは残り幅、余白は上28px・右48px・下20px・左44px。幅960px未満では左右の余白を左ページ20px・右ページ24pxずつに縮める。
- 羊皮紙の地に、[紙肌の画像](../public/assets/hymnal-parchment.webp) と紙端を濃くする淡い色むらを重ねる。紺色の表紙、紙の厚みを表す下辺の線、中央の綴じ目の影、各ページの上下の金の二重線と対角の角飾りで「金彩の装飾写本」を表す。
- 目次は1ページ10曲。通し番号、曲名、点線、検索時の一致度記号、2行目に韓国語名を置く。1行の高さは約58.5px。選択中を背景色で示し、上下キーでも選択できる。
- 目次の見出しは12px・中央揃え・金の二重下線。下のページ送りは「← 前」「n / 全ページ」「次 →」の13px文字とする。
- 右ページは青の番号付き日本語名30px、韓国語名17px、右上に「YouTubeで聴く」の outline ボタンを置き、見出しの下に金の二重線を引く。歌詞は17px・行高2.05とし、歌詞部分だけを内部スクロールする。検索語がなく、歌詞が文字で始まるときは、冒頭1文字を青地に金の飾り文字として表示する。
- 五線譜は300×72を原寸とする SVG とし、幅が足りない場合は縮める。調名・取得案内を横に置く。選んだ長調の調号を描き、楽譜未登録・調取得中・ダウンロード中は押せないようにする。
- 調ボタンは高さ30px、最小幅44px、角丸8px。選択中の再クリックで選択を空にしない。
- 歌詞の一致箇所は背景色を付けず、臙脂・太さ600・2pxの下線・下線位置4pxで示す。検索語がある場合は一致箇所数も表示する。
- ページ送りでは紙の外側を持ち上げ、綴じ目を軸に表から裏へ回す。傾きと陰影を付け、約620msで次の見開きが現れる。「次」は右から左、「前」は左から右。動きを減らす設定では演出を省く。操作はクリックとキーボードによるボタンの起動に対応する。

根拠は [OpenHymnalHome.tsx](../src/components/home/OpenHymnalHome.tsx)、[KeyStaff.tsx](../src/components/home/KeyStaff.tsx)、`globals.css` の `.open-hymnal`・`.book` 関連指定とする。

### 6.2 モバイル（幅768px未満）

- 背景は `/assets/home-bg2.webp`。上部に固定されるヘッダーは `#fffef7` の背景、左右24px・上下8pxの余白とし、ロゴだけを置く。高さ56px等の固定指定はない。ログインボタンは置かない。
- 検索欄は最大幅520px、丸い白67%の背景とする。取得中は欄の外側に臙脂の細いリングを脈動表示する。
- カードの幅はカルーセルの80%とし、次のカードの端が見える横スワイプにする。曲名は日本語名・韓国語名を「 / 」でつなぎ、YouTube へのリンクとする。
- カード右下に曲の詳細を開くボタンを置く。アイコンは白とし、影を付ける。
- ホバー時はカードを4px上げ、色別の光を外側と内側に付ける。押したときは0.98倍にする。カルーセル内には上下28pxの余白を取り、光や浮き上がりを切らない。
- 現在位置を「n / 全件数」で表示し、先読み中の近くのカードには Skeleton を置く。末尾に Luke 21:33 の聖句を表示する。
- 曲の詳細は画面下から出る Sheet とし、高さ85svh・上部角丸18pxとする。上部に取っ手、曲の位置と前後の曲・閉じるボタンを置く。スクロール領域に曲名、韓国語名、調の選択、ダウンロード用の五線譜、歌詞を表示する。歌詞本文は16px・行高1.9、一致箇所は黄色 `rgba(255, 236, 140, 0.92)` で強調する。

根拠は [ホーム](../src/app/home/page.tsx)、[LyricViewer.tsx](../src/components/LyricViewer.tsx)、[ScoreKeyDialog.tsx](../src/components/ScoreKeyDialog.tsx) とする。

## 7. 管理画面

### 7.1 サイドバー・上部バー

- PC は幅256px、折りたたみ時48px。モバイルは左から出る幅288pxのドロワーとする。Ctrl/⌘+B、開閉ボタン、PC の右端のつまみで切り替える。
- PC の開閉状態は `sidebar_state` Cookie に7日間保存する。モバイルのドロワー開閉は別状態で持つ。
- 背景は `#111827`、文字は `#e5e7eb`。選択中は白10%の背景、白文字、左端に `#c0405f` の3px線を内側の影で描く。ホバー時は選択背景の半分の濃さとする。
- 「聖書」「賛美歌」「その他」の見出しで項目をまとめる。項目は高さ32px、角丸あり。未実装項目は文字を薄くし「準備中」を付ける。折りたたみ時は見出し・準備中表示を隠し、項目名は Tooltip で示す。
- 下部に臙脂のアバター・白い頭文字と利用者名を置き、個人スペース・メッセージ・ログアウトのメニューを開く。
- 上部バーは高さ48px。左にサイドバー開閉、右に白い検索欄とログアウトアイコンを置く。検索欄は幅176px、`sm` 以上では240px。
- 画面全体を `100svh` に固定し、右側の本文領域を内部スクロールする。本文のスクロールバーは非表示にする。

根拠は [管理レイアウト](<../src/app/(admin)/layout.tsx>) と [ui/sidebar.tsx](../src/components/ui/sidebar.tsx) とする。

### 7.2 賛美歌一覧

- `/assets/mainmenu-bg5.webp` を背景に、ガラスのカードと濃紺の見出し帯を置く。見出しは18px、帯の余白は上下12px・左右16px、本文余白は24px。
- 表は番号または一致度12%、日本語名34%、韓国語名30%、操作24%の固定列幅とする。検索欄と上部の追加・プレイリストボタンもこの列幅に合わせる。
- 追加は臙脂の通常ボタン、プレイリストは同じ高さ32pxのアイコンボタン。作成中は Spinner とする。
- 行上のホバーは明度を少し落とし、リンクのある行はクリックと Enter で YouTube を開く。操作列は32px・白地・薄い枠・角丸8pxのアイコンボタンで、削除だけ赤とする。
- 名称は2行まで折り返す。表示幅34〜66では0.8倍、67以上では0.66倍に縮め、それでも省略した場合は Tooltip で全文を示す。韓国語は単語を維持して折り返す。
- 初回取得中は Skeleton 行、ページ更新中は前回の行を不透明度50%で残す。ページ番号は臙脂の塗りで現在位置を示し、間を省略記号にする。

### 7.3 賛美歌の追加・更新モーダル

- 最大幅672px・最大高さ92vh、内容が長ければモーダル内部をスクロールする。書体は `.noto-sans`。
- タイトルは左、右上に閉じるボタン。追加時は「すべての項目を入力してください」、編集時は最終更新者・日時を説明文に置く。
- 名称は `sm` 以上で2列、その下にリンク、7行の歌詞欄、枠付きのクラシックスイッチを置く。
- 必須エラーは「入力してください。」を項目の直下に出す。通常のフォーカスは臙脂、エラー時はフォーカスしても赤枠を保つ。
- 下部は左に「リセット／元に戻す」、右に「閉じる」と「追加／更新」。保存中は入力とボタンを無効化し、主ボタンに Spinner を表示する。
- 未保存時の閉じる操作は共通の破棄確認を開き、確認は外側の Dialog の子として配置する。

### 7.4 楽譜アップロードモーダル

- 最大幅448px、書体は `.noto-sans`。タイトルと説明、右上の閉じるボタン、調、ファイル、オリジナルキー、下部ボタンの順に置く。
- 調は6列2段で高さ36px。非選択は薄い枠、選択中は臙脂の塗りと白文字とする。
- ファイルは破線の枠内に「ファイルを選択」と名前・KB数を置き、下に対応形式と30MBの説明を付ける。ファイル・調のエラーは各欄の下に表示する。
- オリジナル指定は説明と Switch を横並びにした枠付きの行とする。下部は「閉じる」「アップロード」を右寄せにする。
- アップロード中は操作を無効化し、閉じる・Esc・背景クリックでモーダルを閉じない。上書き確認は共通の「いいえ」「はい」を使い、「いいえ」では入力を残す。

### 7.5 聖書章節・本人情報・メインメニュー

- 聖書章節入力は `/assets/mainmenu-bg.webp`、明朝体のガラスカードを使う。英語・日本語本文、赤字操作、既存節の案内、その下に書・章・節・保存の欄を置く。狭い画面では下段の項目を縦に並べる。
- 赤字エディタは白地、最小高さ84px、文字16px、角丸4px。通常の内側余白は上下16.5px・左右14px、フォーカス時は2px枠にして余白を1pxずつ減らす。赤字とフォーカスの色は `#c62828` とする。
- 既存節の案内は高さが変わりにくいよう最小高さ24pxを取る。章の選択メニューは最大高さ288pxに抑える。
- 本人情報は `/assets/mainmenu-bg4.webp`、最大幅672px・中央寄せのカード、`.noto-sans` を使う。基本情報・セキュリティ・外部連携を FieldSet と区切りで分け、入力欄は白い不透明な背景とする。
- 本人情報の YouTube 連携スイッチは幅60px・高さ34pxにする。「廃棄」ボタンは灰色地・白文字とする。これらの指定は本人情報画面と `globals.css` に置く。
- ランダム選択は `/assets/mainmenu-bg6.webp`、中央の検索欄、ガラスの結果行とする。読み込み中は5行の Skeleton、未検索・0件は Empty 部品で案内する。
- メインメニューは `md` 以上で3列、それ未満で1列。3枚の画像カードは高さ66vh、下部に黒35%の帯と名称を置く。ホバー時は浮き上がりと各カード色の影、押したときは0.98倍の縮小を付ける。

## 8. トースト・確認ダイアログ

### 8.1 トースト

[FeedbackHost.tsx](../src/components/FeedbackHost.tsx) で Sonner を画面下中央に置き、通常3秒で閉じる。背景は `gray-800`、文字は白・14px、枠なし、小さい角丸、左右16px・上下12pxの余白と影を付ける。トースト自体に明朝体や太字を固定する指定はない。

### 8.2 確認ダイアログ

[ConfirmDialog.tsx](../src/components/ConfirmDialog.tsx) の AlertDialog を共通で使用する。書体は `.noto-serif`。shadcn/ui の標準的なタイトル・説明・下部の操作の構造とし、タイトルごとの色付きの線や別のボタン色は設けない。標準配置は狭い画面で中央揃え、`sm` 以上で左揃えとする。

| 場面                                         | タイトル     | ボタン       |
| -------------------------------------------- | ------------ | ------------ |
| 既存の楽譜・聖書本文の上書き                 | 上書きの確認 | いいえ／はい |
| ログアウト・削除                             | 警告         | いいえ／はい |
| 編集内容の破棄・プレイリスト完了・連携案内等 | お知らせ     | いいえ／はい |

Esc は否定として扱い、外側のクリックで承諾しない。Dialog 内から確認を出す場合は、その DialogContent の子として配置し、Base UI の入れ子のフォーカス管理を使う。

## 9. ログイン

[ログイン画面](../src/app/login/page.tsx)は Vue 版と同じ配置・寸法とし、背景画像の上に青灰色のスモークガラスカードを置く。

| 用途   | 指定                                                                                           |
| ------ | ---------------------------------------------------------------------------------------------- |
| 背景   | `/assets/login-bg.webp` を全画面に固定し、cover で表示                                          |
| 配置   | 上下・左右中央、ページ上下に24pxの余白。高さが足りない場合はスクロール                          |
| カード | 幅360px、最大幅は画面幅から32pxを引いた値、内側余白は上下30px・左右28px、角丸20px               |
| ガラス | `rgba(15, 23, 42, 0.66)`、背景ぼかし24px、彩度115%、白60%の1px枠、外側の影と内側上辺のハイライト |
| 見出し | `NASB1995`、中央揃え、26px、太さ900、白、下の余白22px                                          |
| ラベル | 白、15px、太さ700、入力欄との間隔8px                                                            |
| 入力欄 | 高さ46px、角丸6px、白97%の背景、文字色 `#172033`、枠は `#64748b` を基準にする。フォーカス表示は Nova 標準 |
| ボタン | `primary`、白文字、太さ800、幅いっぱい、高さ46px、角丸6px、白33%の1px枠                           |
| エラー | 淡い赤の背景、赤のメッセージと警告アイコン                                                      |

ユーザー名は `autocomplete="username"`、パスワードは `autocomplete="current-password"` とし、フォーム送信で Enter に対応する。

- 待機表示は成功・失敗とも送信開始から最低3300ms続ける。認証処理が3300msを超えた場合は、応答が届いた時点で結果を反映する。
- 待機中は見出し・ラベル・入力欄の配置を保ったまま隠し、入力欄を無効にする。カードの背景・枠・影をまとめて不透明度33%とし、背景ぼかしを解除する。ボタンの位置と臙脂色を保ち、中央に shadcn/ui 標準の Spinner を表示する。
- 配置と寸法を共通にし、文字の描画やアイコン、スピナーの形と動きは各ライブラリの標準に従う。
- 押下時の効果は各 UI の標準に従う。Vue 版は Vuetify の波紋（ripple）、Next.js 版は shadcn/ui Nova の押している間だけ下へ1px移動する効果を使う。

401 は「ユーザー名またはパスワードが正しくありません。」、その他は「ログインできませんでした。時間をおいて再度お試しください。」を表示する。失敗時は入力内容を保って再試行できるようにする。
